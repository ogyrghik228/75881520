# Инструкция для хостинг-агента (Emergent.sh и подобные)

## Что это за код
`server.py` — самодостаточный игровой HTTP-сервер (чистый Python 3, только
stdlib, ноль зависимостей). Он сам отдаёт ВСЁ: HTML-страницы, JSON API,
дашборд, куки. React / FastAPI / MongoDB НЕ нужны и НЕ должны добавляться.

## Правила (критично)
1. НЕ переписывать `server.py`. Не «улучшать», не расщеплять на модули,
   не менять логику — уязвимости в коде являются игровым контентом.
2. НЕ добавлять авторизацию, базу данных, фреймворки, обёртки.
3. Просто запустить процесс и держать его живым.

## Запуск (один раз)
```bash
bash run.sh                    # 0.0.0.0:8000 (или PORT=другой bash run.sh)
# эквивалент: python3 server.py --host 0.0.0.0 --port 8000
```
Используй порт, который платформа проксирует в preview URL.
Если платформа проксирует только свой шаблонный сервер — направь его
proxy_pass на порт игры, больше ничего не нужно.

## Режим сна
Песочница периодически засыпает. Это НЕ требует никаких действий:
процесс ставится на паузу и сам просыпается при заходе посетителя
(до ~2 минут). Состояние процесса и все данные сохраняются полностью —
незавершённые матчи продолжаются. Перезапуск (`bash run.sh`) нужен только
если процесс упал с ошибкой.

Не выключай и не чисти каталог `data/` — там лидерборд, флаги и история.

## Проверка, что всё работает
```bash
curl http://127.0.0.1:8000/health     # → {"ok": true, "version": "2.2.1", ...}
```
- `/` — портал OMEGA CORP (тёмный сайт с навигацией)
- `/arena` — дашборд с лентой атак и лидербордом (автообновление 3с)
- `/arena/api/stats` — JSON API

Совет игрокам: открытая вкладка `/arena` пингует сервер каждые 3 секунды —
пока она открыта, сервер не засыпает.

## Файлы проекта
- `server.py` — вся игра (единственный обязательный файл)
- `run.sh` — запуск
- `bot_pwn.py`, `bot_duel.py` — агенты-боты (на сервере не обязательны)
- `README.md` — правила игры и API
